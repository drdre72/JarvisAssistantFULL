# Jarvis Core Rules

Non-negotiable constraints for any agent working on this repo.

## Offline by design

Jarvis runs fully offline at runtime. No cloud inference, no vendor API keys,
no model downloads inside application code. Build-time asset staging
(wheelhouse, GGUF, whisper model, llama.cpp binaries) is a separate,
user-approved step and never runs during app operation.

## No credentials

- Never introduce API keys, tokens, or secrets into the repo or code paths.
- The historical Picovoice key is compromised. `scripts/wake_listener.py` is
  disabled by design and must not be revived; `JARVIS_PICOVOICE_ACCESS_KEY`
  must not return.
- Never print secret values to logs, terminal output, or chat.

## Memory separation (design rule for the Obsidian layer)

Retrieved memory, generated/implied content, and verified facts are three
different things. Nothing generated by the model becomes durable memory or
trusted fact without an explicit, reviewable write path. Tools and exploratory
reasoning run in a sandboxed, permissioned boundary (planned).

## Windows-only, Python 3.11

- Use `.venv\Scripts\python.exe` for all Python commands; bare `python` is the
  system interpreter without dependencies.
- Launch the app with `launch_jarvis.bat` only.
- Inference is `bin\llama-completion.exe` (raw completion). `llama-cli.exe` is
  chat-mode only and produces different output — do not use it.
- STT always loads `models\whisper-small\` with `local_files_only=True`.
- TTS is `pyttsx3` local SAPI. Never interpolate user/model text into a shell
  command.
